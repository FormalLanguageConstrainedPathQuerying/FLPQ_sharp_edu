# Detailed Plan: Task 292 — Deduplicate merged Arroyuelo reachability edge labels

## Task description (verbatim)

```
292. Fix duplicate edge labels in Arroyuelo RPQ reachability step graphs. When an input edge and a derived (computed) edge connect the same pair of vertices, `RpqGraphViz.renderGraphWithDerived` merges their labels; deduplicate the merged label so it never repeats the same component verbatim (e.g. `X, X` -> `X`, `X, Y, X` -> `X, Y`). Keep the merge behaviour otherwise unchanged.
**[USER GUIDANCE]**: Only exact repeated components are removed (`X, X` -> `X`); the merge itself is kept. This deliberately does not change the current example `data/example_graph_demo_big.txt` + `data/example_regexp_demo.txt` (step 1), whose merged labels (`a, (a·a)∗`) have no repeated text — the duplicate-looking overlap there is between labels of *different* edges (a self-loop and an input+derived edge) and is out of scope for this task.
```

## Overview

The Arroyuelo reachability step graph keeps the input edges and adds one red-bold edge per
true cell of the handled node's Boolean result matrix. When a derived pair `(u, v)` is also
an input edge, `RpqGraphViz.renderGraphWithDerived` merges the input terminal label with the
derived subexpression via its private `merge` helper, producing e.g. `"a, (a·a)∗"`.

This task makes that merge duplicate-safe: the resulting label must never contain the same
component verbatim twice. It is a small, self-contained change to one private helper plus a
test and the two docs that describe the merge behaviour.

## Subtasks

### S1: Deduplicate repeated components in the merged derived/input edge label

**Status:** Resolved

**Code:** `src/FLPQ.Printers/RpqGraphViz.fs` — replace the private `merge` helper in
`renderGraphWithDerived` with a duplicate-safe version that splits the input edge label on
`", "`, appends the derived label as one component, removes exact repeats preserving first
occurrence order, and re-joins with `", "`.

**Tests:** `tests/FLPQ.Printers.Tests/RpqGraphVizTests.fs` — add `renderGraphWithDerived`
unit tests: (a) an input edge whose label equals the derived label renders the label once in
both DOT and TikZ; (b) an input edge with two terminal symbols where the derived label equals
one of them keeps the other symbol and drops the repeat (`X, Y, X` → `X, Y`). Reuse
`TestHelpers.rpqExampleGraph` and `Nfa.fromTransitions` for the two-symbol edge.

**Docs:** `docs/developer/rpq-graph-viz.md` (update the `renderGraphWithDerived` description
and the merge design decision), `docs/developer/arroyuelo-reachability-step-viz.md` (update
the Derived-Edge Graph section and the merge design decision).

**Spec:**

- New merge behaviour:
  ```fsharp
  let merge (original: string) (derived: string) =
      let parts =
          [ if original <> "" then yield! original.Split(", ")
            if derived <> "" then yield derived ]
      parts |> List.distinct |> String.concat ", "
  ```
- `original` is the (possibly escaped) input-edge label already comma-joined by
  `graphEdgeLabel`; `derived` is a single label (the node's subexpression) and must not be
  split, so it is appended as one component.
- The empty-string special cases of the previous helper are preserved by only yielding
  non-empty parts; `"" , d` -> `d`, `o, ""` -> `o`, `"", ""` -> `""`.
- Exact string equality is the dedup key (per the user guidance); distinct components that
  merely share a substring (`a` in `(a·a)∗`) are both kept, so the current example output is
  unchanged.
- Output `dot` and `tikz` remain generated by `RpqGraphDot.toDot` / `RpqGraphTikz.toTikz`;
  no changes to those modules (keeps `RpqGraph*` byte-identical for Belyanin goldens).
