# AzimovCfpq Module

**Tags:** cfpq, context-free, azimov, matrix, fixed-point, algorithm
**Kind:** algorithm
**Module:** AzimovCfpq
**Source:** `src/FLPQ.CFPQ/AzimovCfpq.fs`

**Used by:** CFPQ CLI runners (S7), tests
**Book reference:** Chapter 12, Section sec:CFPQ_MatrixBased, listing alg:graphParse

> **Abstract:** Azimov's matrix-based CFPQ algorithm as one generic semiring-parametrized core: convert the grammar to CNF, initialize each nonterminal's matrix from its terminal and epsilon rules, then run the batch fixed point `T <- T union (T x T)` until an iteration changes nothing. On top of the fixed point: the Boolean answer matrix, single-path extraction (LAGraph PR #8), and all-simple-paths enumeration (LAGraph PR #9).

## Purpose

Decides which pairs of vertices are connected by a path whose label sequence is generated by a context-free grammar, and — depending on the semiring — recovers one witness path or all simple witness paths. The algorithm follows book listing `alg:graphParse`: one matrix per nonterminal, initialized from the direct derivations, then iterated to a fixed point with binary-rule products.

## Type and Function Signatures

```fsharp
type WcnfRule<'t, 'nt> =
    | Epsilon of Nonterminal<'nt>
    | Terminal of Nonterminal<'nt> * 't
    | Binary of Nonterminal<'nt> * Nonterminal<'nt> * Nonterminal<'nt>

val classifyRules: Grammar<'t, 'nt> -> WcnfRule<'t, 'nt> list

type CfpqCell<'nt> = { Nt: Nonterminal<'nt>; Row: int; Col: int }

type CfpqStep<'nt, 'elem> =
    { Iteration: int
      ChangedCells: CfpqCell<'nt> list
      Matrices: Map<Nonterminal<'nt>, Matrix<'elem option>> }

type CfpqResult<'nt, 'elem> =
    { Matrices: Map<Nonterminal<'nt>, Matrix<'elem option>>
      Steps: CfpqStep<'nt, 'elem> list
      Iterations: int }

val evaluate: Semiring<'elem> -> (int -> 'nt) -> Grammar<'t, 'nt> -> CfpqGraph<'t> -> CfpqResult<'nt, 'elem>
val answer: CfpqResult<'nt, bool> -> Nonterminal<'nt> -> Matrix<bool>
val extractSinglePath: WcnfRule<'t, 'nt> list -> CfpqGraph<'t> -> Map<Nonterminal<'nt>, Matrix<PathIndex option>> -> Nonterminal<'nt> -> int -> int -> Trans<'t> list option
val enumerateAllPaths: WcnfRule<'t, 'nt> list -> CfpqGraph<'t> -> Map<Nonterminal<'nt>, Matrix<AllPathsElem option>> -> Nonterminal<'nt> -> int -> int -> Trans<'t> list list
```

- `classifyRules` — maps each grammar rule to its WCNF shape and rejects any other right-hand side with `ArgumentException`. The algorithm runs on the CNF conversion, so this is a total check, not a prefilter.
- `evaluate` — the full algorithm: `toCnf` with the caller-supplied fresh-nonterminal function (the same pattern as `Valiant.parse`), classification, matrix initialization from terminal/epsilon rules, then the batch fixed point. Returns the final matrices, the productive steps in iteration order (cells sorted by nonterminal name, row, column; each step also snapshots the full matrix state after that iteration, for step-by-step visualization), and the total number of loop applications including the final no-change one.
- `answer` — the reachability result: the start nonterminal's matrix as a plain Boolean matrix.
- `extractSinglePath` / `enumerateAllPaths` — see below.

## The Batch Fixed Point

Each iteration takes a **snapshot** of all matrices, computes every binary-rule product `B x C` (via `Matrix.mxmi` with the semiring's cell operations), and add-accumulates each product into its left-hand side's matrix. This is exactly the book's `T <- T union (T x T)`: within one iteration no product sees another product's result.

Consequences, verified against the book's worked example (Chapter 12):

- The loop performs 13 applications on the example grammar and graph; 12 are productive (one new nonterminal per step) and the 13th changes nothing and terminates the loop. `CfpqResult.Iterations = 13`, `Steps` has 12 entries.
- An in-place (Gauss-Seidel) variant would converge faster but would not reproduce the book's T₀…T₁₃ trace, so the batch semantics are deliberate.

Complexity: one iteration is O(|rules| · n³) — each binary rule costs one `mxmi` product of two n×n matrices. For the Boolean semiring every cell flips at most once, so there are at most |N|·n² productive iterations; for the path-based semirings a cell can improve several times (height decreases, split lists grow), so the productive-iteration count is bounded by the number of distinct cell values rather than by |N|·n².

## Path Extraction and Enumeration

### extractSinglePath (LAGraph PR #8)

Walks the `PathIndex` matrices back through the grammar:

- A height-1 cell is a direct derivation: epsilon (only when `i = j` and an epsilon rule exists), else the one terminal edge matching a `Terminal` rule.
- A taller cell splits at `Middle` through a binary rule `A -> BC` whose subpath heights are consistent (`max pb.Height pc.Height + 1 = p.Height`); the left and right subpaths are extracted recursively and concatenated.

Returns `None` for no path, `Some []` for epsilon, else the edge sequence as `Trans<string>` records (`From`, `Label`, `To`). Height strictly decreases on every recursive call, so extraction terminates.

### enumerateAllPaths (LAGraph PR #9)

Walks the `AllPathsElem` matrices and yields exactly the **simple** paths (no repeated vertex):

- A `Base` cell yields the direct derivations: epsilon when `i = j`, plus one edge per matching terminal rule.
- Each split vertex `k` of a `Splits` cell joins a `B`-path `i..k` with a `C`-path `k..j` for every binary rule `A -> BC`; the sentinel split yields the direct derivations.
- A concatenation is kept only if it is a simple path (`isSimplePath`).

The recursion carries a visited set, initially `{i, j}`; a split vertex already visited is skipped and each used split is added to it. This bounds the depth by the vertex count and is sound for completeness: after `toCnf`, no right-hand-side nonterminal of a binary rule derives epsilon (only the fresh start symbol has an epsilon rule, and it never appears on a right-hand side), so every split vertex of a simple path is an internal vertex and is never skipped by the visited filter.

## Design Decisions

| Decision | Rationale |
| --- | --- |
| Batch (Jacobi) fixed point, not in-place | Reproduces the book's worked-example trace T₀…T₁₃ exactly; the golden test (S3) pins it |
| `toCnf` inside `evaluate`, fresh names via a caller-supplied function | The algorithm requires WCNF; callers pass the original grammar plus the fresh-name function (the `Valiant.parse` pattern), so the core stays generic over `'t`/`'nt`. Deterministic fresh names (`Grammar.freshStringNonterminal`) keep results reproducible |
| `Matrices` covers every CNF nonterminal (LHS, RHS, start) | The book's T₀ initializes each nonterminal to the empty matrix; even a rule-less grammar (empty language) yields a queryable result instead of a missing key |
| `Steps` records only productive iterations, sorted cells | The step list is the visualization input (S7); deterministic order makes golden output stable |
| Each `CfpqStep` snapshots the full matrix state after its iteration | The book's T_k figures show every nonterminal matrix at each iteration, not just the changed cells; the snapshot makes a step self-contained for rendering without replaying earlier steps |
| `Iterations` counts the final no-change application | Matches the book's loop structure: the test that "nothing changed" is itself one application of the update rule |
| Extraction/enumeration take `rules` + `matrices` separately, not a `CfpqResult` | They are pure functions of the fixed-point data; tests can build matrices by hand without running `evaluate` |
| allPaths enumeration filters to simple paths at join time | LAGraph PR #9 semantics: "all paths, not all walks or trails"; the visited set plus the simple-path filter together yield exactly the simple paths |
